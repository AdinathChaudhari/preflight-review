# Changelog

## 1.1.0 — 2026-11-06
Thorough by coverage, lean by model. 1.1 started as "exhaustive review over cost" ; on 2026-11-07 the cost defaults were replaced by the lean ones below (decision 15) after a 74-file incremental deep run planned 1214 model calls (~$30) and hit the 5-hour usage limit: 773 of its 835 completed calls were Opus security votes on ruff `S` findings such as S101 in tests, 3 votes each, and auto mode went deep only because eval fixtures contained migration files.

- Coverage defaults: `budget_usd: null` (no run budget, and no per-call `--max-budget-usd` unless a budget is set), `mode: auto`, `profile: assertive`, `verifier.cap: null`, `nitpicks.per_file/per_run: null`, `sweep: true`. The round-2 nitpick strip is removed; `max_rounds` stays and only prints its message. Per-call timeout is `call_timeout_s: 3600`. Deep turn limits: finders and security 18, verifier 10. Effort per stage (`effort:` quick `low`, standard `medium`, deep `high`) is passed as `--effort`, never to a Haiku model. A call that ends with `error_max_turns` is no longer retried at the same limit.
- Lean model defaults (decision 15; deviates from Anthropic's `/code-review` plugin, which finds and validates bugs on Opus): Sonnet for every finder lens in every mode (`finder`, `finder_deep`, `finder_rules`), the security lane and the sweep; Haiku for triage (`triage.haiku: true`, now on by default), learnings rerank and the walkthrough; Opus only as the adjudicator of escalated splits (`adjudicator: opus`; Fable stays configurable, with the generic `adjudicator_fallback`). `verifier_major` is unused and kept so older configs load. Per-role sources: `docs/reference.md`, Models per stage.
- Verification: up to `verifier.votes: 3` Sonnet votes per finding (quick mode: 1). Two run in parallel and decide when they agree; a third runs only when they disagree, and the majority decides. A critical finding without a unanimous vote, or a security finding at major or above with no majority, goes to one Opus adjudication; any other split is Unverified with no Opus call. The reason records the tally and model, for example `votes 2/2 CONFIRMED (sonnet)` or `votes 2/3 CONFIRMED, 1 REFUTED (sonnet); adjudicated by opus: ...`. Tool findings (gitleaks, osv-scanner, secret-files, ruff, ast-grep, zizmor, actionlint, shellcheck) never go to a model verifier and are reported as tool-verified. Trivial and nitpick-lane findings skip the verifier, are reported labelled `unverified-nit` and counted apart from confirmed findings, and never count as verifier failures. A partly failed vote set is not a verifier failure; all votes failing keeps the 1.0 demote-and-fail path. Each vote is its own cost entry; the verdict cache key includes vote count, verifier model and adjudicator.
- ruff: `tools.ruff.test_ignore` (S101, S105, S106, S107, S108, S311) is not reported on `tools.ruff.test_paths` (`tests/**`, `**/test_*.py`, `**/*_test.py`, `**/conftest.py` and similar). ruff `S` (security-lint) findings elsewhere are reported at minor, not major: they are unverified pattern matches and must not raise merge risk on their own.
- Depth scales with the change, never truncated mid-run (decision 14, after Anthropic's managed Code Review): new `mode: auto`, the default, resolves once per run before any model call to `deep` when any changed path matches `auto.deep_paths` (generic globs for migrations, auth/security, secrets/env, CI/deploy, prompts and agent instructions, scoring/grading/billing/payment code) and to `standard` otherwise; paths under `tests/`, `test/`, `eval/`, `fixtures/`, `docs/` and similar, and files in risk tier test or docs, never count. An explicit `--mode` or config `mode` wins. Deep mode differs from standard by turns, effort and one sweep per run. The report header has a `Mode:` line and the manifest records `mode_requested`, `mode_resolved`, `crucial_paths` (up to 10), the pre-run `estimate` and the run's `calls_by_stage` / `calls_by_model`. Supersedes the `mode: deep` default of decision 7.
- Pre-run estimate and depth menu: before the first model call a rough USD, wall-time and planned-call estimate is printed (`~36 calls: 8 finders, 2 security, ~15 verify (~1 adjudicated), 10 triage, 1 walkthrough`), priced per stage model (Sonnet 1/2, Haiku 1/40 of Opus) from rates refitted to the measured 74-file run and the seeded eval. Above `confirm_above_usd` (default 5, null = off) a terminal gets a menu of quick / standard / deep, each with its own estimate and call count, Enter = the resolved mode, plus cancel; without a terminal (hook, skill, CI) no model is called, and a "not started" report lists each depth's estimate and its command (`--mode quick|standard|deep --yes`) and exits 1. New `review --yes` skips the menu. `eval` always passes `--yes`. The Run section's Cost line shows calls and USD by stage and by model.
- Opting back into caps: `--budget-usd N` or `budget_usd: N` (also restores per-call caps); `verifier.cap: N`; `verifier.votes: 1`; `nitpicks.per_file` / `nitpicks.per_run` (applied under `profile: chill`); `--mode standard|quick`; `sweep: false`; `profile: chill`; any `models.*` key (for example `finder: opus`). `--budget-usd` can add a cap but cannot remove one a repo's `.preflight/config.yaml` sets; set `budget_usd: null` there instead. Config is read from the base branch, so a config key takes effect once it is merged there; use `--budget-usd` / `--mode` for the current run.
- Sweep: in deep mode one sweep call per run gets every candidate found so far and the list of changed files (plus the packet when the run has a single batch) and reports only new ones; they are deduplicated by stable id, prefiltered, clustered and put through the same votes. A failed sweep marks the run incomplete.
- Recall-first finders: `system.md` v2 asks for every candidate with a concrete failing input and a quoted line, leaving filtering to the verifier. Finder output has a required `coverage` trace and an optional `finder_confidence`. A lens that answers empty without coverage or reads is retried once on `finder_deep` (`finder:<lens>#retry`). Verifier v3: CONFIRMED needs a quote of the failure path for the named input; a finding naming no reachable input is REFUTED. Lens checklists added to correctness, contracts_tests (data contracts, test strength), data_concurrency (migrations, bootstrap parity, atomic publishing) and security (recall).
- New lenses and tools: path-gated `deploy_ci` lens (Sonnet) that runs only when workflows, deploy manifests, Dockerfiles, shell scripts or runbooks change, added automatically (`auto_lenses: true`); `zizmor` on by default, `actionlint` and `shellcheck` opt-in; built-in `secret-files` check (committed `.env*`, private keys, credential files), always on, critical and never merged away; `key_consumers` candidate signals for new keys nothing reads. An `extensions/` package lets a module register lenses, a repo detector and extra ast-grep rule folders. Security verifier v3 overrides the exclusions that refuted committed env files, prompt-boundary injection and wildcard CORS with credentials.
- Prefilter: prompt files, `SKILL.md`, `CLAUDE.md`, `AGENTS.md` and `.claude/**/*.md` are behaviour (risk tier `source`), not docs. A doc finding is kept when its evidence quotes another changed file, code or doc. New `docs_review: auto|on|off` (default `auto`): docs-only diffs get the correctness and contracts_tests lenses with a doc-consistency instruction instead of being skipped; `off` restores the 1.0 skip. Haiku triage never approves a prose doc unless `docs_review: off`.
- DEGRADED banner: an enabled tool that had work in the diff but is missing, fails or returns unparseable output marks the report `DEGRADED` (top banner, Result line, tool table, JSON `degraded` list, summary suffix). Outcome and exit code are unchanged. A tool error no longer aborts the run.
- Eval: new seeded cases `committed_env_file`, `prompt_injection_grade`, `cors_wildcard_credentials`, `plan_progress_drift`, `prompt_md_kept`, `workflow_run_pr_deploy`, `runbook_job_order`, `prompt_rule_contradiction`, `vacuous_test`, `migration_bootstrap_drift` (18 planted bugs plus one benign control). Fake backend: 17 of 18 found, precision 1.0, ep_recall 0.944.
- Review fixes before merge: `docs_review: off` runs only path-gated lenses on a docs-only scope, and a scope left with only docs after triage skips model stages. A doc finding on a changed line may also cite an unchanged file that exists in the repo (`docs_review: auto|on`). `secret-files` treats `.env.<x>.example`-style names as templates and flags a `.pem` only when it holds a PRIVATE KEY block. The verdict cache key includes the adjudicator, and a fallback-adjudicated verdict is not cached. A subprocess timeout (`error_timeout`) is not retried. A tool that ran on part of its input (osv-scanner with one failed manifest) reads `ran partially`, not `did not run`. Security verifier v4 adds overrides for CI/deploy trust findings and for credentials inside logged URLs. A lens that returns findings without coverage on a code batch is noted as shallow. The Unverified section is collapsed. `init` no longer imports CodeRabbit's `reviews.profile`. `doctor` and the Run section name config keys still pinned at their 1.0 defaults (`profile: chill`, `mode: standard`, `budget_usd: 1.5`, `nitpicks` 2/5, `verifier.cap: 15`; `models.finder: sonnet` is no longer flagged now that Sonnet is the 1.1 default again): a config written by 1.0 `init` keeps 1.0 behaviour until those keys are removed from the base branch's `.preflight/config.yaml` (removing them on a feature branch takes effect once merged; pass `--budget-usd` / `--mode` for this run). `doctor` reads the config from the base branch, as `review` does, and checks the working-tree file with a note when the base branch has none. `init --with-ast-rules`, which installs the generic rules from `ast_rules/rules/`; repo-specific lenses, prompts and rules live only in extension modules. New seeded cases `verify_exit_zero`, `lexical_version_sort`, `json_non_object`, `pipe_hides_push_failure`, `db_url_guard_hostaddr`, `dotenv_test_reload`, `migration_early_return_stamp` and clean controls `json_constant_ok`, `pipefail_ok`, `natural_sort_ok`, `migration_dialect_skip_ok` (fake backend: 24 of 25, precision 1.0, ep_recall 0.960).
- Eval noise fixes after the first real-model run on 1.1 (recall 0.96, precision 0.57): security verifier v5 labels exclusions E1-E18 and precedents P1-P12 (bare numbers let an adjudicator read "exclusion 7", hardening, as "precedent 7", GitHub Actions; the duplicate exclusion 16 is now E16/E17), and override 4 lifts only the trigger-check exclusions, so an extra gate on a workflow whose missing trigger check is already reported stays under E7. Seed fixes: `workflow_run_pr_deploy` carries `scripts/deploy.sh` and a `Makefile` and gains a second golden (no concurrency group); `migration_dialect_skip_ok` creates `items` and `pg_trgm` in its base migrations and adds the missing 0002 and a downgrade; `natural_sort_ok` uses `str.isdecimal()`. Seed scripts with a shebang are committed executable. Results add `precision_reported` (report only), `n_unverified` and per-case `unverified`; `precision` keeps counting Unverified findings. Fake backend: 25 of 26, precision 1.0, ep_recall 0.962.
- Usage-limit circuit breaker: a call that fails with the Claude usage/rate limit (`hit your ... limit`, `usage limit`, `rate limit`, HTTP 429; not `overloaded_error`) trips a run-level flag, is not retried, and every call not yet started is skipped without a subprocess and recorded as `paused: usage limit`. The run outcome is the new `paused` (exit 1): the Result line gives the reset time, `N of M calls done` and the resume command, findings so far are reported, and round and findings state are not advanced. Successful calls are saved to `.preflight/runs/<report>/calls.json`; new `review --resume` re-runs the same scope and round, replays calls whose key (role, model, prompts incl. packet, schema, turns, effort) matches, and calls the model only for the rest; a changed diff falls back to a normal run. Before this, one real deep run kept launching ~230 calls after the limit, all of which failed, leaving 52 findings unverified.
- gitleaks: a repository `.gitleaks.toml` is passed with `--config` to both scans (the worktree scan runs on a temp copy that would not see it). This repo's file allowlists PEM test fixtures whose body is the literal `\nREDACTED\n`, which gitleaks flagged as critical on every run; a real key is still reported (live test).
- Measured: the seeded eval on the exhaustive defaults (deep, 30 cases, judges sonnet+opus): precision 0.569, recall 0.960, USD 27.48 before the eval noise fixes; precision 0.700, precision_reported 0.729, ep_recall 0.962 (25/26, miss `prompt_md_kept`), F1 0.810, USD 26.94 after (`docs/measurements.md`). The lean defaults have not been measured: cost, recall and precision need a re-run. zizmor parsing is tested on sample JSON only.

## 1.0.3 — 2026-11-03
- Miss learned from: CodeRabbit flagged a stale archive `_INDEX.md` that still described a guard the branch had removed. A replay of 1.0.2 on the same commit showed the finder reported it, then `prefilter()` dropped it as "docs file" and the report said "0 findings, complete".
- Prefilter fix: a finding on a `.md`/`.rst`/`.txt` file is kept when any `evidence[]` entry cites a non-doc file changed in the diff (a doc-code consistency claim). The check is file-level, because in the real miss the cited code line was unchanged context (the guard was added then removed on the branch). Findings with prose-only evidence, or evidence in files outside the diff, are still dropped as "docs file".
- Report: new `## Dropped (N)` section lists each dropped candidate as `stage: title (file:line) — reason` (first 50; the rest stay in `.dropped.jsonl`), so a wrong drop is visible to a human. The `Dropped: N (see …)` line under Findings stays.
- Eval: golden row for the PR #44 miss in `eval/golden/seed-cases.jsonl` (the commit SHA in the miss write-up had two extra characters; the row uses the real 40-char SHA, now checked by `test_seed_cases`). New multi-commit seeded layout (`before/` tree + `commits/NN-name/` trees, per-item `file` in `expected.json`) and seeded case `stale_doc_ledger`: commit 1 adds a coupon shape guard and a ledger row describing it, commit 2 removes the guard, the ledger stays stale.
- Measured: fake backend seeded recall 0.750 → 0.875 (6/8 → 7/8, `stale_doc_ledger` is the change). Real models after the fix: recall 1.000, precision 1.000 on 8 seeded bugs, USD 1.64 (`eval/results/20261103-125034-seeded.json`, local; `eval/results/` is git-ignored). Real models with the 1.0.2 prefilter on `stale_doc_ledger` alone: 0/1, but the raw finder output shows the finders returned no finding at all in that run, so that miss was finder variance, not the prefilter.
- Workflow rules in the `init` RULES.md template: under "Always check", when a commit removes or renames a symbol, search the branch's changed docs for it; under a new "Workflow" heading, re-run `preflight-review review --incremental` after any commit that answers review findings, before pushing. The `/preflight` skill says the same after a fix. (`learn` was not used: learnings are "do not flag" suppressions, not rules.)
- Known: the real PR #44 finding was labelled `lane: nitpick`, `severity: trivial`. With the fix it reaches the verifier; under profile `chill` a confirmed trivial nit is reported within the nit caps, but an unverified one is still dropped as below profile, and eval scoring counts inline-lane findings only.

## 1.0.2 (2026-10-30) — first public release

- Report-only pre-push review CLI: `preflight-review review`.
- Claude Code plugin with a `/preflight` skill.
- Report-only pre-push hook: `install-hook`; set `PREFLIGHT=0` to skip.
- Pipeline: scope from the merge base with base-branch config; deterministic tools (gitleaks, osv-scanner, ruff, ast-grep); a context packet with callers, co-change, guidelines and learnings; risk-ordered batches with a shared cache prefix.
- Four finder lenses plus an Opus security lane with source-to-sink trace, then a fresh-context verifier.
- Policy: hide pre-existing issues, no repeats across rounds, nit cap.
- Honest coverage: a "Not reviewed" section, merge risk reported as unknown when coverage is incomplete, and a `.dropped.jsonl` of discarded findings.
- Output: `<repo>-PR<##>-preflight-review-<##>.md`, a JSON twin and a manifest.
- `respond`, `learn` and `learn --propose` to close the loop on findings.
- `import-coderabbit` to turn existing review comments into a golden set.
- Eval harness with seeded, clean and golden suites.
- `init` with optional `--with-ast-rules` and `.coderabbit.yaml` import.
- Budget cap per run.
